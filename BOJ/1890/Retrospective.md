### 아이디어

```text
solve: 현재좌표에서 도착점까지의 경우의 수
```

```text
최초에는 도착점에서 거꾸로 거슬러가는 top down으로 생각함. 로직 자체는 맞으나 이러면 3차원 배열 필요해서 귀찮음. ai한테 물어보니 정방향으로 하라해서 이렇게 함. 물론 이것도 top down임.
```

## 3) 표준 풀이
### 핵심 아이디어
- 정석 접근
```text
bottom up방식.
dp테이블의 값은 여기까지 오는 경로 수.
출발점부터 시작해서 점점 더하면 자연스럽게 도착점 값 나옴;;;
시간복잡도는 같으나 재귀 안해도 됨.
```
```c++
#include <bits/stdc++.h>
using namespace std;

int main(){
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<vector<int>> v(n, vector<int>(n));
    for(auto& row : v)
        for(int& x : row) cin >> x;

    vector<vector<long long>> dp(n, vector<long long>(n, 0));
    dp[0][0] = 1;

    for(int r = 0; r < n; ++r){
        for(int c = 0; c < n; ++c){
            if(dp[r][c] == 0 || v[r][c] == 0) continue;
            int d = v[r][c];
            if(c + d < n) dp[r][c + d] += dp[r][c];
            if(r + d < n) dp[r + d][c] += dp[r][c];
        }
    }
    cout << dp[n-1][n-1];
}
```

```markdown
### 탑다운(메모이제이션)이 좋을 때
- 필요한 상태만 일부 방문할 때. 모든 상태를 계산할 필요가 없으면 도달하는 상태만 계산해서 빠릅니다.
- 계산 순서를 잡기 어려울 때. 점화식은 쉬운데 어떤 순서로 채워야 할지 애매하면, 재귀가 순서를 알아서 풀어 줍니다.
- 상태 공간이 크고 희소할 때. 상태가 map이나 비트마스크처럼 불규칙하면 배열을 다 채우는 건 낭비입니다.
- 점화식을 그대로 코드로 옮기고 싶을 때. 구현이 빠르고 실수가 적습니다. 코테 초반 접근으로 좋습니다.

### 바텀업(타뷸레이션)이 좋을 때
- 모든 상태를 어차피 다 계산해야 할 때. 재귀 호출 오버헤드가 없어서 상수가 작고 빠릅니다.
- 재귀 깊이가 깊을 때. N이 10⁵~10⁶ 같은 선형 DP는 탑다운에서 스택 오버플로가 날 수 있습니다.
- 공간을 줄이고 싶을 때. 이전 행이나 직전 몇 개 값만 필요하면 롤링 배열로 O(N²)를 O(N)으로 줄일 수 있습니다. 탑다운은 이게 어렵습니다.
- 순서가 명확할 때. 배낭, LIS, 격자 경로처럼 앞에서부터 채우면 되는 문제입니다.
```
